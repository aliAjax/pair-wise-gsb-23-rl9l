# hxwl-09 限值版本与巡检判定台

面向半导体洁净室巡检的**限值版本化 + 判定追溯**应用。解决「限值一改、旧巡检记录也跟着变、说不清当时按哪套标准判定」的问题。

## 技术栈

React 19 + Vite + TypeScript + CSS，数据持久化在浏览器 localStorage（无需后端）。

## 本地运行

```bash
npm install
npm run dev
```

开发端口：5109

## 功能规则

### 管理员：限值版本维护与发布

- 按 ISO 5 / 6 / 7 / 8 等级维护 0.3μm、0.5μm、5.0μm 三个通道上限（粒/m³），空值表示该通道不设限
- 基于最新版本新建**草稿**，同一时间只允许一份草稿；草稿可反复保存，**不出现在巡检员的生效版本中，不参与判定**
- 草稿校验通过（非负整数 + 版本说明必填）后可发布，发布即冻结、只读，并成为巡检员默认判定版本
- 每个已发布版本可查看「按此版本判定的记录」清单，用于对账

### 巡检员：选房间、选生效版本录入

- 房间带出 ISO 等级，生效版本只能从已发布版本中选择（默认最新）
- 录入三通道计数时实时预览：越界通道高亮，提交后超限记录自动进入**异常区**并显示每个越界项（实测值 / 上限 / 超出量）
- 异常区支持填写处理备注并标记已处理

### 版本与结论的不可变追溯

- 每条记录提交时把**当时版本的限值快照**与判定结论一起冻结进记录
- 之后发布再高的新版本，旧记录仍显示原限值、原结论，不会被重判
- 补录不覆盖原记录：在原记录上「补录修正」会另建一条修正记录，锁定原房间与原判定版本，**修正原因必填**，并与原记录互相引用

### 持久化

- 版本、记录、当前角色均保存在 localStorage（`cleanroom-limit-console:v1`），重开页面后版本与记录仍可对上
- 页脚「恢复演示数据」可重置为内置种子（V1、V2 已发布 + V3 草稿 + 含异常与修正的示例记录）
